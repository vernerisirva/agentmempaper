    Canonical source evidence
    OpenSaCseparates the agent's research decisions from program execution. The coding agent chooses the next steps and writes a Python program that combines software development kit (SDK) calls with local computation and file operations. The library supplies typed interfaces for search, content fetching, reranking, and model calls; the host executes the program. Selected execution results return to the agent, which decides whether to answer or investigate further. These observations can include source excerpts, extracted records, computed summaries, or errors. Figure 2 illustrates a possible labor-statistics program. Indepen- dent searches cover unemployment, employment, and earnings series; the program merges rankings, selects URLs, fetches data, and retains responses before returning records. Grouping known requests leaves the agent to identify gaps and decide on follow-up queries.

    Canonical source evidence
    Research workflows may require different search services, content readers, or model endpoints. Provider dispatch separates these back- end choices from program composition, allowing each capability to be configured independently. Adapters map shared capability contracts to each backend's request and response formats. They register through Python entry points; the runtime routes calls to the configured adapter for each capability. Included adapters support Serper and Jina Reader, HTTP backends, and model endpoints compatible with the OpenAI API. Users can combine services, replace backends while retaining program logic, or compare provider configurations with the same program. Developers can connect new services through custom adapters without modifying the core library (Figure 2).

    OpenSaCpairs the library with a companion Search as Code skill that guides agents in composing research programs. The library supplies executable capabilities; the skill explains when to batch in- dependent requests, preserve sources, select observations, and reuse evidence. This guidance is provided through the skill mechanisms of coding agents such as Codex and Claude Code [2, 6]. The skill works with the agent's existing Python execution and file tools.     OpenSaCenables coding agents to compose retrieval operations in inspectable programs and retain evidence for reuse. With skill guidance, it reduced execution time and model token use on both benchmarks; accuracy improved on BrowseComp, while row F1 declined slightly on WideSearch. Improving how agents use SaC-like paradigms remains open. Better provider services could expand source coverage and improve the relevance and reliability of evidence. Skill guidance could be op- timized through evaluation, including methods that let agents pro- pose and test revisions.
