Quality reviewed

The study presents a clear, well-scoped system that addresses a well-identified failure mode of flat memory in test-time continual learning. The methodology is thoroughly detailed, formal bounds are derived, and empirical results demonstrate substantial token and training-time efficiency gains on objective external tasks.

The manuscript acknowledges limitations including the small number of tasks (two financial domains), evaluation against only one primary baseline (ACE), single-run evaluation without repeated trials, and the fact that reading the index retains residual growth rather than strict end-to-end O(1) complexity.

    We use ACE as our workhorse for realizing GraphMemory. GraphMemory changes ACE at precisely two interfaces: what the Generator (f) reads and what the Curator (O) writes. Instead of exposing the complete playbook to every query, we prepend a retrieval stage; instead of writing only bullet- point updates, the Curator can also write relations between them. The resulting adaptation loop is RETRIEVE–GENERATE–REFLECT–CURATE, as illustrated in Figure 2. For retrieval, we maintain a compact index containing each node's identifier and a short key, but not its full bullet-point content. Given a query, the Retriever reads this index and selects a small set of entry nodes. We then perform a deterministic breadth-first traversal from those entries, expanding neighbors in order of learned edge utility, under fixed hop, node, and token budgets.
