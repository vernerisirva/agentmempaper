About

How Paper Scout works

A daily updated library of papers on Engram-style model memory, learned lookup tables, and transferable memory mechanisms.

Implementation references

Separate from the scholarly paper list: DeepSeek Engram repository, Megatron-LM integration discussion (PR 3689), and Megatron-LM feature request (issue 3382).

These links provide implementation context; their status is not monitored automatically.

Updates and coverage

New means added to this library within the past 24 hours, not newly published. Initial submission, revision and first-seen dates remain separate.

Each provider has four logical daily queries and one result page per query, capped at 25 records. Incomplete windows and provider errors are retained in diagnostics. Foundational IDs are ingested separately; historical search is an explicit one-time operation.

Quality assessment uses deterministic metadata checks by default, up to four papers per run, with zero model calls. Missing full-paper evidence remains unknown.

What Paper Scout tracks

This library tracks Engram and closely related model-integrated conditional memory: learned lookup tables, hashed n-grams, memory readers, transfer, training, capacity scaling and efficient execution. Related mechanisms are not assumed to be identical architectures.

Sources

The daily scout queries arXiv, OpenAlex, and Semantic Scholar. Source metadata can disagree, lag, or contain future publication dates from publisher feeds.

Deduplication

Candidate papers are canonicalized by DOI, arXiv ID, Semantic Scholar ID, OpenAlex work ID, then normalized title, first author, and year. The dashboard also collapses duplicate titles while preserving alternate source links.

Relevance screening

Highly relevant papers substantively study these mechanisms. Product-key memories, neural memory layers, model-memory editing and test-time memory need a concrete connection and may remain review candidates. Name collisions, generic RAG and conversation storage are excluded. Negative findings and unsuccessful replications remain eligible; relevance is not an endorsement.

Scholarly-quality assessment

Scholarly quality is assessed separately from topic relevance. The optional, versioned assessment uses paper-type-aware deterministic evidence checks and may use a configured LLM to validate the structured result. Scores are confidence- and scope-qualified; missing full text remains unknown rather than being treated as weak.

Automated assessments are triage aids, not peer review. Evidence, concerns, assessor provenance, rubric version, and assessment scope are available in paper records and exports.

Manual curation

Optional curation can pin, annotate, override, or hide papers in the static dashboard without deleting anything from SQLite state.

Structured paper cards

The cumulative library links each paper to a structured detail page and sidecar JSON. These static records are meant for human review and future agent workflows; fields are provenance-aware, incomplete extraction is shown as “Not extracted yet”, and the sidecar schema is published at paper-card.schema.json.

Structured cards are generated from title, abstract or summary, metadata, deterministic screening, and curation notes. They do not claim that Paper Scout has deeply read the full paper.

Limitations

Relevance screening can produce false positives or false negatives. Semantic Scholar rate limits may occur. Source metadata can be wrong, and future publication dates may reflect source metadata rather than actual availability.
