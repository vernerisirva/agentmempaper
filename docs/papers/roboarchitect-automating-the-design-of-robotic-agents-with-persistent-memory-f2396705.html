Quality reviewed

RoboArchitect provides a well-substantiated contribution to embodied agent design. The experimental validation strictly separates training episodes used for code evolution from held-out evaluation splits (unseen scenes and unseen tasks) scored using objective benchmark task success metrics.

The authors transparently document limitations, including an exploration cap of five iterations, evaluation confined to simulated manipulation environments without physical hardware testing, and focus on pick-and-place/basic manipulation tasks rather than complex in-hand dexterity.

    Recent work shows that a frozen robot policy performs far better inside an agent harness, where control code decides when to query the policy, consult vision tools, or command the arm directly. Yet today these harnesses are built by hand and redesigned for each new robot or benchmark. We show that harness design can be automated, offering a strong alternative to finetuning on a novel setup. In ROBOARCHITECT, a coding model observes a robot's rollouts, diagnoses failures, and iteratively revises the harness around the frozen policy. The harness evolves on a set of episodes for its optimization and is evaluated on held-out scenes and tasks. Without updating any model weights, ROBOARCHITECTraises average success from 9.7% to 43.3% on unseen scenes (4.5×) and from 12.7% to 40.2% on unseen tasks (3.2×), across multiple benchmarks and policies.     ROBOARCHITECToptimizes the harness around a frozen policy, as illustrated in Fig. 2. It starts from a harness that passes the policy's actions through unchanged and repeats an empirical optimization loop: the harness runs on the training episodes, a coding model observes the recorded rollouts, diagnoses the failures and refines the harness. These "training" episodes serve only to optimize the harness:no weights are updated, and the final harness is evaluated on separate held-out episodes (§4.1). Over iterations, the harness grows into a highly performant robotic agent that, as needed, follows the policy, consults auxiliary tools, or commands the arm directly, and it can carry experience in a persistent memory. Auxiliary tools.Beyond the base policy, the harness can query auxiliary pretrained tools (§4.1), including language models, vision-language models, object detectors, segmentation models, pointing models, and grasp pose generators.     Scaling cap of iterations.As shown in Figs. 10 to 12, harness performance on the training episodes improves consistently across iterations. However, this work uses a fixed maximum of 5 optimization iterations (§4.1). More iterations may yield further gains, but the point at which returns saturate remains to be explored. Nevertheless, even with a moderate budget of only 5 iterations (§B), ROBOARCHITECTachieves substantial gains that transfer to held-out settings. More complex manipulation.A natural next step is extending ROBOARCHITECTto tasks with richer contact dynamics, such as dexterous in-hand manipulation or tool use, where the space of failure modes is larger than in pick-and-place. The range of control routines and memory structures that automated evolution can discover in these settings is an interesting open question. Sim-to-real transfer.All evaluations run in simulation.
